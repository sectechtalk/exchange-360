# Portal column mapping

Design rule: every Ex360 table uses the column names of the matching Microsoft portal page, with that page's default column set. Ex360 adds a column only when it is necessary, and each one is listed under "Conflicts" below.

**Source** says where the portal names came from:

- **Docs**: Microsoft Learn lists the page's default columns (link given).
- **Live**: read from the portal page itself while signed in to the tenant (2026-11-22).
- **Known**: the portal's column labels as Ex360 has seen them, not yet read live from the tenant.
- **Unchanged**: no portal list shows this, or the portal defaults could not be confirmed, so the headers stay as they were.

Every list table keeps the per-column sort and search menu. Selecting a row opens the details flyout, the way the portal does. Facts that used to be extra columns now live in that flyout.

## Conflicts

1. **Licenses: the portal says "Available licenses" and "Assigned licenses" (plural).** You wrote "Available license" and "Assigned license". Ex360 uses the portal's plural wording. The portal's "Assigned licenses" shows used out of total, so Ex360 shows it as 2/5. Part number and Status moved to the row's flyout.
2. **Licenses appear in two portals with different columns.** M365 admin center > Billing > Licenses (Name, Available licenses, Assigned licenses) and Entra > Licenses > All products (Name, Total, Assigned, Available, Expiring soon). Ex360 follows the M365 admin center, as you asked.
3. **Shared mailboxes appear in two portals.** EAC > Mailboxes (Display name, Email address, Recipient type, Archive status, Last modified time) and M365 admin center > Teams & groups > Shared mailboxes (Name, Email). Ex360 follows the EAC, because that is the page the pane links to.
4. **Groups appear in two portals.** EAC > Groups (Group name, Group email, ...) and M365 admin center > Active teams & groups (Name, Email, ...). Ex360 follows the EAC.
5. **Distribution and mail-enabled security groups share one Ex360 page; the EAC has a tab for each.** Decision: show every column from the source tabs and leave cells blank where they don't apply. Group type stays so the two kinds can be told apart.
6. **Columns Ex360 had that the portal does not, now moved into the row flyout:** shared mailbox Full Access count, direct sign-in, forwarding and sent items copy; room capacity, location and booking; group members, owners, mail from outside, moderation and joining; dynamic group filter; Microsoft 365 group members, guests and owners; license part number and status; quarantine "Who can release it" and policy name; role group roles, members and last modified. Decision: keep them in the flyout for now, as close to the source view as possible.
7. **Columns kept although the portal has none (necessary for the page's job):** Domains and DNS keeps its per-domain DNS panels below the table (the old DNS summary column is gone); Entra roles keeps Members; App access keeps Exchange roles; Trace details keeps Time from previous event and What it means; the per-portal links under each object name (PRs #25 and #26) stay.
8. **Pages with no portal equivalent (headers unchanged):** Mailboxes that forward (uses EAC mailbox labels plus the EAC forwarding flyout's labels, Forwarding address and Keep a copy of forwarded email), Role assignments and scopes, Management scopes, Application access policies, Exchange admin audit (Search-AdminAuditLog), move requests, preset policy summary, connection filter, Config review, Org config, every Single recipient analysis table (Applies / Why), Header analyzer, Outlook PC check, and the New hire teaching tables.
9. **Read live on 2026-11-22 and now matched:** User roles, Migration endpoints, Quarantine policies, Tenant allow list (senders), DLP policies, Sensitivity labels and label policies, Retention policies and labels, eDiscovery cases, Purview role groups. DLP rules have no list of their own in Purview (they sit inside a policy), so their table is unchanged. Entra sign-ins and audit logs follow the new views the portal opens by default; the legacy views had different columns.
10. **Detail tables (Setting / Value, Field / Value)** are flyout or property layouts, not portal lists, so they keep their two columns.
